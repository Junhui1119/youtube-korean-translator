# V1.5 Stabilization and Backend Plan

Status: Draft

## Goal

V1.5 should turn the current locally working V1 into a more stable seed-user version, without taking on the full complexity of V2 realtime speech recognition.

V1.5 keeps the same core product:

```text
YouTube Korean CC captions
-> translate to Chinese
-> render overlay in the video player
```

The focus is reliability, polish, light backend integration, and feedback collection.

## Non-Goals

- No audio capture.
- No speech recognition.
- No billing system.
- No full user account system unless needed for a small test group.
- No complex dashboard before the core extension is stable.

## Phase 1 - Release Readiness

Tasks:

- Add missing extension icons referenced by `manifest.json`.
- Confirm unpacked extension loads cleanly in Chrome.
- Add a simple manual QA checklist for:
  - YouTube normal video with Korean CC
  - YouTube livestream with Korean CC
  - video without CC
  - switching videos inside YouTube SPA
  - enabling/disabling popup switch
  - Google translation mode
  - DeepL translation mode
- Update README to describe V1.5 status and known limitations.

Acceptance:

- A new tester can load the extension without missing-resource errors.
- Manual QA steps are documented and repeatable.

## Phase 2 - Runtime Stability

Tasks:

- Fix MV3 service worker settings initialization race.
  - `GET_ENABLED` and `TRANSLATE_TEXT` should wait for storage initialization.
- Prevent stale translation responses from overwriting newer captions.
  - Use `requestSeq` or compare returned text with the latest caption text before rendering.
- Narrow the `MutationObserver` scope.
  - Prefer YouTube player/caption container.
  - Fall back to `document.body` only when necessary.
- Add client-side request pacing.
  - Keep debounce.
  - Add minimum interval or in-flight dedupe for high-frequency subtitle changes.
- Improve failure states.
  - Distinguish translation API failure, disabled state, no captions, and backend unavailable if backend is enabled.

Acceptance:

- Fast subtitle changes do not display old translations.
- Disabled state remains correct after reload/service worker cold start.
- Watching a long video does not create obvious UI lag.

## Phase 3 - Translation Quality

Tasks:

- Improve glossary matching.
  - Sort glossary entries by Korean term length before replacement to avoid short terms replacing inside longer terms.
  - Add tests for overlapping terms.
- Add glossary reload guidance.
  - Document that users need to reload the extension after editing CSV.
- Expand game terms based on actual videos tested.
- Add a small evaluation file with sample Korean captions and expected Chinese terms.

Acceptance:

- Common game terms are translated consistently.
- Glossary changes can be tested with `npm test`.

## Phase 4 - Optional Backend Translation Proxy

Purpose:

Start using the backend in a low-risk way before V2.

Tasks:

- Add `POST /api/translate`.
  - Input: source text, source language, target language, optional engine.
  - Output: translated text, engine, latency.
- Keep the existing direct-browser translation path as fallback.
- Add extension setting:
  - direct mode
  - backend mode
- Move shared API keys to backend only if using backend mode.
- Add basic rate limiting.
- Add request logs for latency and failure rate.

Acceptance:

- Extension can translate through backend when configured.
- If backend is unavailable, extension can fall back to direct mode or show a clear error.
- API keys are not hardcoded in extension source.

## Phase 5 - History and Feedback

Tasks:

- Connect existing history API to the extension.
  - Record video id, title, channel, last position.
  - Do not store subtitle text by default.
- Add simple feedback capture.
  - Good/bad translation button or lightweight popup feedback.
  - Store only minimal metadata unless the user explicitly submits text.
- Add privacy copy for what is stored.

Acceptance:

- Tester sessions can be reviewed by video metadata.
- Users understand that subtitle text is not stored by default.

## Phase 6 - Seed User Readiness

Tasks:

- Prepare installation instructions for non-developers.
- Create a short test script for seed users.
- Add known limitations:
  - needs existing Korean CC
  - no no-caption speech recognition yet
  - Google translation may rate limit
  - DeepL requires user key or backend configuration
- Add a simple changelog.

Acceptance:

- 5-20 users can test the extension and report useful feedback.
- Issues can be grouped by playback, translation quality, setup, or performance.

## Recommended Architecture for V1.5

```text
Chrome Extension
  content.js
    - caption detection
    - overlay rendering
    - stale response protection

  background.js
    - settings initialization
    - translation cache
    - direct translation or backend translation proxy

  popup.js
    - enable/disable
    - engine/backend mode
    - DeepL key if direct mode remains supported

FastAPI Backend (optional in V1.5)
  /api/translate
  /api/history
  /api/hello

PostgreSQL
  users or temporary tester identities
  history_records
  usage_logs
```

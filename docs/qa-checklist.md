# 手动 QA 清单（v1.5-alpha）

在 Chrome 里加载 `extension/` 目录（`chrome://extensions/` → Developer mode → Load unpacked）后，按顺序过一遍：

## 基础场景

- [ ] 打开一个有韩语 CC 的普通 YouTube 视频，开启 CC，插件在 5 秒内开始显示中文叠加字幕。
- [ ] 打开一个有韩语 CC 的 YouTube 直播，确认字幕持续更新，没有明显卡顿。
- [ ] 打开一个没有 CC 字幕的视频，5 秒后应出现"请先点播放器 CC 按钮 → 选择 Korean"提示。
- [ ] 在 YouTube 站内点击跳转到另一个视频（不刷新页面），字幕状态正确重置，新视频的字幕能正常翻译。
- [ ] 点击 popup 开关关闭插件：中文字幕消失，状态显示"翻译已关闭"。重新打开：立即恢复翻译，状态显示"已启用，监听字幕中…"。
- [ ] 不填 DeepL Key 时，popup 显示当前引擎为 Google，翻译正常。
- [ ] 填入有效 DeepL Key 并保存，popup 显示当前引擎切换为 DeepL，翻译质量明显更好。

## v1.5-alpha 专项回归

- [ ] **设置初始化竞态**：在 popup 里关闭插件 → 打开 `chrome://extensions/` → 点击插件的"Reload"强制 service worker 冷启动 → 立刻刷新一个有 CC 的 YouTube 页面。预期：插件保持关闭状态（不应该短暂地又开始翻译）。
- [ ] **旧翻译覆盖新字幕**：找一段语速很快、字幕频繁切换的视频（或反复快进/后退触发字幕跳变），确认叠加层里显示的中文字幕内容，先后顺序上不会出现「已经切到新字幕，却还显示上一句的翻译」。
- [ ] **Observer 范围收窄**：打开开发者工具 Performance 面板，在同一个视频页面上滚动/操作页面其他区域（不是字幕区域），确认没有触发不必要的翻译请求（Network 面板里没有对应的 translate 请求）。

## 已知限制

- 需要视频本身已有韩语 CC 字幕；无字幕的语音识别翻译在 v2 规划中，尚未实现。
- Google 翻译免费接口可能触发限流（429），已加自动重试，但仍可能短暂显示错误状态。
- DeepL 需要用户自备免费版 API Key。

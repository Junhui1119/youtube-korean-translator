# Design: v1.5-beta 后端翻译代理 + 请求日志

Date: 2026-07-07
Status: Approved

## 目标

- 将 DeepL API key 从扩展移至后端，消除密钥暴露风险
- 为翻译请求添加结构化日志，支持延迟和错误率观测
- 接口预留 `engine` 字段，为未来 DeepL+Claude 管道保留扩展点
- 后端不可用时扩展静默降级到直连 Google，popup 状态灯变黄提示用户

## 非目标

- 不加后端翻译缓存（扩展侧已有 200 条 LRU 缓存）
- 不做用户账号体系（沿用临时 X-User-Id 方案）
- 不实现 DeepL+Claude 管道（接口预留，v2 实现）
- 不做日志持久化到数据库（stdout 结构化日志足够）

---

## 后端设计

### 新增接口

```
POST /api/translate
Authorization: Bearer <token>
Content-Type: application/json
```

请求体：
```json
{
  "text": "안녕하세요",
  "engine": "deepl"
}
```

- `text`：必填，非空字符串，最大 5000 字符
- `engine`：可选，默认 `"deepl"`，当前只支持 `"deepl"`

响应体（200）：
```json
{
  "translated": "你好",
  "engine": "deepl",
  "latency_ms": 342
}
```

错误响应：
- `401` — Bearer token 不匹配
- `422` — 参数校验失败
- `502` — DeepL 调用失败（扩展据此触发降级）

### 鉴权

后端从环境变量 `TRANSLATE_TOKEN` 读取 token。请求头 `Authorization: Bearer <value>` 与其比对，不匹配返回 401。

`.env.example` 新增：
```
TRANSLATE_TOKEN=your-random-secret-here
```

### 日志中间件

每次 `POST /api/translate` 请求完成后，向 stdout 打一行 JSON：

```json
{
  "event": "translate",
  "engine": "deepl",
  "text_len": 12,
  "latency_ms": 342,
  "status": "ok",
  "ts": "2026-07-07T10:23:01Z"
}
```

失败时 `status` 为 `"error"`，附加 `"error"` 字段描述原因。**不记录原文和译文内容**（隐私保护）。

实现为 FastAPI middleware，仅作用于 `/api/translate`，不影响其他路由。

## 扩展设计

### 新增设置项

`chrome.storage.local` 新增两个字段：
- `backendUrl`：字符串，后端地址（如 `https://xxx.onrender.com`），默认空
- `backendToken`：字符串，Bearer token，默认空

### popup.html 改动

新增一个折叠区域"后端设置（可选）"：
- 后端地址输入框
- Token 输入框
- 保存按钮

留空表示直连模式，现有逻辑不变。

### 状态灯新增黄色状态

| 颜色 | 含义 |
|------|------|
| 灰 | 翻译关闭 |
| 绿 | 翻译中（正常） |
| 黄 | 降级模式（后端不可用，已切换 Google） |

### background.js 翻译逻辑

```
收到 TRANSLATE_TEXT 消息
  ↓
已配置 backendUrl + backendToken？
  ├─ 是 → POST /api/translate
  │       成功(200) → 缓存并返回译文，状态绿
  │       失败(非200 / 网络错误 / 超时) →
  │           降级直连 Google
  │           发 BACKEND_DEGRADED 消息给 popup（状态灯变黄）
  │           返回译文
  └─ 否 → 现有逻辑（直连 Google 或 DeepL）
```

降级后**不自动恢复**，需用户在 popup 关闭再开启"显示字幕"才重试后端，避免每次字幕变化都重试。

后端请求超时设为 **5 秒**，超时视为失败触发降级。

## 文件变更清单

**后端：**
- `backend/main.py` — 新增 `POST /api/translate` 路由 + token 鉴权依赖
- `backend/translate_service.py`（新建）— DeepL 调用逻辑
- `backend/middleware.py`（新建）— 翻译日志中间件
- `backend/.env.example` — 新增 `TRANSLATE_TOKEN`
- `backend/tests/test_translate_api.py`（新建）— API 测试

**扩展：**
- `extension/background.js` — 翻译逻辑加后端分支 + 降级处理
- `extension/popup.html` — 新增后端设置区域
- `extension/popup.js` — 读写 backendUrl / backendToken，监听 BACKEND_DEGRADED

---

## 验收标准

1. `POST /api/translate` 携带正确 token + 文本，返回 200 和译文
2. token 错误返回 401
3. DeepL key 只在后端 `.env` 中，扩展代码中不出现
4. 后端日志在 stdout 可见，包含 latency_ms 和 status
5. 后端地址填写后，popup 状态灯在后端不可用时变为黄色
6. 后端不可用时扩展仍能翻译（降级 Google）
7. 未填写后端地址时，扩展行为与 v1.5-alpha 完全一致

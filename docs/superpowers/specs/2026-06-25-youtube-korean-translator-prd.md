## 1. 概述

一个 Chrome 浏览器插件，自动把 YouTube 视频里**已显示的韩语 CC 字幕**实时翻译成**中文**，在原韩语字幕**正下方**追加一行中文。

纯前端实现，无后端服务器、无需注册登录、无需 API key。用户装上插件、打开韩语字幕，就能看懂。

## 2. 背景与问题

韩语游戏直播与主播在中文圈拥有大量死忠粉，但 YouTube 不提供实时中文翻译。

**这些粉丝现在怎么看？—— 等别人「搬运熟肉」（人工翻译搬运）。** 搬运的特点决定了我们的机会：

| 搬运熟肉 | 优势 | 劣势 |
|----------|------|------|
| 人工翻译 | 准、地道、懂梗 | — |
| 时效 | — | 延迟几天到几周 |
| 覆盖 | — | 只搬热门主播的**精剪高光**，长直播 / 冷门主播 / 完整内容几乎没人搬 |
| 主动性 | — | 只能看别人选的，不能看自己想看的 |

**所以我们的价值主张不是「比搬运翻得更好」（打不过人工），而是：**

> **「搬运没覆盖到的内容 / 你现在就想看的内容，立刻能看懂。」**

推论：用户的对照组是「根本没熟肉、看不懂」，因此**「大致看懂」就是从 0 到 1 的胜利**——免费翻译引擎的质量很可能够用，价值集中在**完整长内容、冷门、即时**。

## 3. 目标用户

| 优先级 | 画像 | 场景 |
|--------|------|------|
| 首要 | 看少数固定韩语主播的**中文死忠粉** | 追主播没被搬运的内容（长直播、录播、冷门） |
| 次要（预留） | 看任何韩语 YouTube 视频的中文用户 | 量更大，但 v1 不为其做特化 |

**冷启动打法**：不做泛化营销，挑 1–2 个在中文圈有死忠、但搬运覆盖差的主播，去其粉丝聚集地（超话 / QQ群 / 贴吧 / Discord）精准投放。死忠粉痛点最尖锐、最愿装插件、最能自发安利，且**能容忍 v1 的粗糙**，给我们试错空间。

## 4. 目标与非目标

### v1 要做的（目标）

- 读取 YouTube 播放器中**已显示的韩语 CC 字幕**文字
- 实时翻译成中文（免费 Google 翻译网页接口）+ **术语库校正**
- 在原韩语字幕**正下方**追加一行中文（韩中双语并存）
- 一个总开关（开启 / 关闭插件），状态持久化

### v1 明确不做的（非目标 / YAGNI）

- ❌ 语音识别 / 无字幕视频（= 无字幕纯直播，留待下一阶段，是核心大赌注）
- ❌ 字号 / 显示位置选择 / 自由拖拽（v1 位置固定在原字幕下方）
- ❌ 纯中文 / 纯双语切换开关（v1 默认双语并存）
- ❌ 其他目标语言（v1 固定中文）
- ❌ 付费翻译引擎（先用免费跑通，做成可替换层，挂了再切）
- ❌ 账号、生词本、翻译历史（后续阶段的产品愿景，不在 v1）
- ❌ 标题 / 简介 / 评论翻译

## 5. 核心假设与场景边界

**v1 的边界不是「直播 vs 录播」，而是「页面上有没有韩语 CC 字幕」。** 能不能跑，取决于有没有字幕可读：

| 内容类型 | 有韩语 CC？ | v1 支持？ |
|----------|------------|-----------|
| 录播视频（主播上传） | 几乎都有 | ✅ |
| 直播 + 开了实时字幕 | 有时有（延迟可能略大） | ✅ |
| 直播 + 无字幕 | 无 | ❌（需语音识别，下一阶段） |

因此：

1. 使用时需先在播放器打开韩语 CC 字幕（CC 按钮 → 选 Korean）。
2. 视频必须有韩语字幕轨。
3. 完全无字幕的内容 v1 不支持——这正是下一阶段（语音翻译）的落点。

这条假设是 v1 能以纯前端、低复杂度实现的根本原因。

## 6. 用户故事

- **US-1 自动翻译**：作为不懂韩语的死忠粉，我想在打开韩语 CC 后自动在原文下方看到中文，以便无额外操作就能看懂我爱的主播。
- **US-2 开关控制**：作为用户，我想用一个开关随时开/关翻译，且我的选择下次还在。
- **US-3 失败可读**：作为用户，翻译接口临时失败时我仍想看到原韩语字幕（不空白），以便不丢信息。
- **US-4 引导提示**：作为新用户，没打开韩语字幕时我想得到明确提示，以便知道怎么用。
- **US-5 切换视频**：作为连续看的用户，我想在 YouTube 内切下一个视频后翻译仍正常，以便不用刷新。

## 7. 功能需求

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| FR-1 字幕监听 | 监听 YouTube 字幕容器 DOM 变化，提取最新韩语字幕文本 | 字幕变化时稳定取到对应韩语文本，不漏不重 |
| FR-2 翻译调用 | 经 background 调用免费 Google 翻译接口（ko→zh-CN），解析译文。**引擎封装为可替换的一层** | 返回正确中文；接口结构变化或失败有处理；切换引擎只动这一层 |
| FR-3 术语校正 | 机翻产出后，用术语库（`glossary/ko-zh-game-terms.csv`）对游戏术语/梗/人名做覆盖 | 命中术语库的词按库内译法显示；编辑 CSV 即可更新，无需改代码 |
| FR-4 双语渲染 | 在原韩语字幕**正下方**追加一行中文（原文不隐藏） | 中文显示在原字幕下方、清晰可读、不挡关键画面 |
| FR-5 开关与持久化 | Popup 提供总开/关，状态存 `chrome.storage.local` | 切换即时生效；重开浏览器/页面后保留 |
| FR-6 失败回退 | 翻译失败时回退只显示原韩语 + 小提示，不崩溃、不空白 | 模拟接口失败时仍显示原韩语 |
| FR-7 缓存与防抖 | 相同字幕命中缓存不重复请求；变化过快时防抖/限流 | 重复行只请求一次；高频变化下请求被合理合并 |
| FR-8 引导与重初始化 | 未检测到字幕时提示打开韩语 CC；SPA 切页时重新初始化监听 | 无字幕时有提示；站内切视频后无需刷新即可继续 |

## 8. 非功能需求

- **翻译质量**：常规对话**大致看懂即可**；游戏术语以术语库为准，命中的词必须翻对。
- **延迟 / 实时性**：字幕出现 → 中文显示，端到端延迟目标 **< 1 秒**。
- **稳定性 / 可用性**：不得使视频卡顿或崩溃；接口失败优雅回退；高比例字幕能成功翻译。
- **轻量 / 零门槛**：无需注册、无需配置 API key、零后端，装上即用。

## 9. 成功指标

**北极星指标：安装量 + 单次使用时长。**

| 指标 | 含义 | 测量方式 |
|------|------|----------|
| 安装量（主） | 规模 / 拉新信号 | Chrome 商店后台，免费 |
| 单次使用时长（主） | 真用 / 粘性信号 | **种子死忠粉访谈估计**（v1 不加遥测） |
| 翻译成功率（质量护栏） | 成功翻译条数 / 总字幕条数 + 零崩溃 | 人工 / 本地手测 |
| 端到端延迟（质量护栏） | 字幕出现 → 中文显示 | 人工 / 本地手测 |

**v1 坚持零后端**：因此「单次使用时长」靠访谈估计，不做自动上报；精细留存 / 时长度量等到有后端阶段再正经做。

## 10. 范围外与后续阶段（Roadmap）

按价值与难度排列，均不在 v1：

1. **显示个性化**：多档位置（顶部 / 底部）、**自由拖拽**、字号
2. **目标语言切换**（中文 / 英文等）
3. **替换为更高质量翻译引擎**（DeepL / Claude）—— 触发条件见 §11
4. **无字幕直播的语音识别**：捕获标签页音频 → ASR（如 Whisper）→ 翻译。难、可能需后端（WebSocket + STT + LLM）。**这是 `CLAUDE.md` 完整愿景的核心大赌注。**
5. **账号体系与个性化**：登录、翻译历史、一键收藏的韩语生词本。需后端 + 数据库。
6. **标题 / 简介 / 评论翻译**

## 11. 开放问题与风险

| 风险 / 问题 | 说明 | 应对 |
|------|------|------|
| **免费接口单点命门** | 非官方 Google 翻译接口，可能限流 / 被封，真出事产品当天就挂 | **已接受此风险**换零成本快速验证；引擎做成可替换层；**触发 Plan B 条件**：接口频繁失败影响体验，或验证成功要正经做 → 切 DeepL / Claude |
| 紧贴原字幕易错位 | 中文贴原字幕正下方，YouTube 改版可能错位 | 渲染逻辑集中、易改；发现错位及时修；必要时退化为独立浮层 |
| YouTube DOM 变动 | 改版导致字幕容器选择器失效 | 监听逻辑集中；及时更新选择器 |
| 术语库覆盖度 | 初期术语少，游戏梗 / 人名仍可能翻砸 | 用户按需补充 CSV；不改代码即可迭代 |
| 时长指标量化 | 零后端无法自动测「单次使用时长」 | v1 靠种子用户访谈估计；精细度量待后端阶段 |
| 延迟可控性 | 受网络与接口响应影响，<1 秒为目标非硬保证 | 缓存 + 防抖降请求量；以主观体验为准持续观察 |

## 1. 概述

一个 Chrome 浏览器插件，自动把 YouTube 视频里**已显示的韩语 CC 字幕**实时翻译成**中文**，并叠加显示在视频画面上。

纯前端实现，无后端服务器、无需注册登录、无需 API key。用户装上插件、打开韩语字幕，就能看到中文。

## 2. 背景与问题

韩语游戏直播与视频在中文圈拥有大量受众，但 YouTube 本身不提供实时中文翻译：

- **看不懂**：不懂韩语的中文观众无法理解主播说什么、字幕写什么。
- **体验割裂**：现有变通方式（手动复制翻译、切到第三方翻译网站、等别人搬运熟肉）都把人拉出观看场景，且无法实时跟上直播节奏。
- **空白机会**：YouTube 自带的「自动翻译字幕」覆盖不稳定、入口深、对游戏/直播口语术语翻译质量参差。

一个「装上即用、字幕直接变中文」的轻量插件，能以最低门槛填补这个空白。

## 3. 目标用户

| 优先级 | 画像 | 场景 |
|--------|------|------|
| 首要 | 看韩语**游戏直播**但不懂韩语的中文观众 | 实时跟直播，强调低延迟、口语/游戏术语翻译 |
| 次要（预留） | 看任何韩语 YouTube **视频**的中文用户 | 点播视频，对延迟不敏感，但量更大 |

v1 以首要画像为设计核心；功能与架构上不做妨碍次要画像的特殊化，为后续扩展预留空间。

## 4. 目标与非目标

### v1 要做的（目标）

- 读取 YouTube 播放器中**已显示的韩语 CC 字幕**文字
- 实时翻译成中文（使用免费的 Google 翻译网页接口）
- 把中文译文叠加显示在视频上
- 一个开关（开启 / 关闭插件），状态持久化

### v1 明确不做的（非目标 / YAGNI）

- ❌ 语音识别 / 翻译无字幕的视频（留待后续阶段）
- ❌ 标题、简介、评论翻译
- ❌ 双语对照显示（默认只显示中文译文；以后易加）
- ❌ 英文等其他目标语言（v1 固定中文；以后可加切换）
- ❌ Claude / DeepL 等付费翻译引擎（先用免费的跑通，再考虑替换）
- ❌ 账号、生词本、翻译历史（这些是后续阶段的产品愿景，不在 v1）

## 5. 核心假设

插件通过**读取 YouTube 已经渲染出来的韩语字幕文字**来工作。因此：

1. 使用时用户需先在播放器里打开韩语 CC 字幕（CC 按钮 → 选 Korean）。
2. 视频必须有韩语字幕轨（创作者上传的或 YouTube 自动生成的，绝大多数韩语视频都有）。
3. 完全没有任何字幕的视频，v1 不支持。

这条假设是 v1 能以纯前端、低复杂度实现的根本原因，也是 v1 与「完整产品愿景（语音实时翻译）」的主要边界。

## 6. 用户故事

- **US-1 自动翻译**：作为不懂韩语的观众，我想在打开韩语 CC 字幕后自动看到中文译文，以便无需任何额外操作就能看懂内容。
- **US-2 开关控制**：作为用户，我想用一个开关随时开启/关闭翻译，以便在不需要时回到原始观看体验，且我的选择下次还在。
- **US-3 失败可读**：作为用户，当翻译接口临时失败时，我想仍能看到原始韩语字幕（而不是空白），以便不丢失信息。
- **US-4 引导提示**：作为第一次使用的用户，当我没打开韩语字幕时，我想得到一句明确提示，以便知道该怎么用。
- **US-5 切换视频**：作为连续看视频的用户，我想在 YouTube 内切到下一个视频后翻译仍然正常工作，以便不用刷新页面。

## 7. 功能需求

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| FR-1 字幕监听 | 监听 YouTube 字幕容器的 DOM 变化，提取最新韩语字幕文本 | 字幕变化时能稳定取到对应韩语文本，不漏不重 |
| FR-2 翻译调用 | 把韩语文本发到 background，调用免费 Google 翻译接口（ko→zh-CN），解析译文 | 给定韩语文本能返回正确中文；接口结构变化或失败有处理 |
| FR-3 叠加渲染 | 把中文译文渲染为视频上的叠加层 | 译文显示在视频内、清晰可读、不遮挡关键画面 |
| FR-4 开关与持久化 | Popup 提供开/关开关，状态存于 `chrome.storage.local` | 切换后立即生效；重开浏览器/页面后状态保留 |
| FR-5 失败回退 | 翻译失败时回退显示原韩语 + 小提示，不崩溃、不空白 | 模拟接口失败时仍显示原韩语字幕 |
| FR-6 缓存与防抖 | 相同字幕命中缓存不重复请求；字幕变化过快时防抖/限流 | 重复行只请求一次；高频变化下请求被合理合并 |
| FR-7 引导与重初始化 | 未检测到字幕元素时提示用户打开韩语 CC；YouTube SPA 切页时重新初始化监听 | 无字幕时有提示；站内切视频后无需刷新即可继续工作 |

## 8. 非功能需求

- **翻译质量**：中文译文读起来通顺、语义准确，游戏/直播常见口语与术语尽量不离谱。
- **延迟 / 实时性**：从韩语字幕出现到中文译文叠加显示，端到端延迟目标 **< 1 秒**，以跟得上直播节奏。
- **稳定性 / 可用性**：插件不得使视频卡顿或崩溃；翻译接口失败时优雅回退；尽可能高比例的字幕能成功翻译。
- **轻量 / 零门槛**：无需注册、无需配置 API key，安装后即可使用。

## 9. 成功指标

| 维度 | 指标 | 目标方向 |
|------|------|----------|
| 翻译质量与准确性 | 译文通顺/准确的主观抽检通过率（人工抽样评估） | 抽检通过率高，术语翻译可接受 |
| 延迟与实时性 | 字幕出现 → 中文叠加显示的端到端延迟 | < 1 秒 |
| 稳定性与可用性 | 字幕翻译成功率（成功翻译条数 / 总字幕条数）；无视频卡顿/崩溃 | 成功率高；零崩溃 |
| 用户采用与留存 | 安装量、活跃用户数、开关保持「开启」的用户比例 | 持续增长；多数用户保持开启 |

> 说明：v1 不内置遥测/数据上报（保持纯前端、零后端）。质量与延迟指标以人工/本地手动测量为主；采用与留存指标可借助 Chrome Web Store 的安装统计观测。引入更精细的留存度量需等到有后端阶段。

## 10. 范围外与后续阶段（Roadmap）

按从易到难、价值递增排列，均不在 v1：

1. **双语对照显示**（韩语 + 中文）
2. **目标语言切换**（中文 / 英文等）
3. **替换为更高质量翻译引擎**（Claude / DeepL）
4. **无字幕视频的语音识别**：捕获标签页音频 → ASR（如 Whisper）→ 翻译。难度高，可能需后端（WebSocket + STT + LLM）。这是 `CLAUDE.md` 里完整产品愿景的核心。
5. **账号体系与个性化**：注册登录、翻译历史、一键收藏的韩语生词本。需后端 + 数据库。
6. **标题 / 简介 / 评论翻译**

## 11. 开放问题与风险

| 风险 / 问题 | 说明 | 应对 |
|------|------|------|
| 非官方翻译接口稳定性 | 免费 Google 翻译网页接口非官方，可能有频率限制或偶发不可用 | v1 接受此风险；做好失败回退；后续可平滑替换为 Claude / DeepL |
| YouTube DOM 结构变动 | YouTube 改版可能导致字幕容器选择器失效 | 监听逻辑集中、易改；发现失效及时更新选择器 |
| 翻译质量天花板 | 免费引擎对游戏/直播术语翻译质量有限 | v1 接受；roadmap 第 3 项替换更高质量引擎 |
| 延迟可控性 | 受网络与接口响应影响，<1 秒为目标非硬保证 | 缓存 + 防抖降低请求量；以主观体验为准持续观察 |
| 成功指标量化 | 纯前端无遥测，质量/留存难以精确量化 | v1 以人工抽检 + 商店统计为主；精细度量待后端阶段 |

# V1.5-alpha Stabilization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the four v1.5-alpha deliverables from `docs/2026-07-01-v1.5-stabilization-and-backend-plan.md` (Phase 1-2) and `docs/2026-07-01-review-todo.md` (P0-P1): fix the MV3 service-worker settings-init race, stop stale translation responses from overwriting newer captions, narrow the `MutationObserver` scope, and ship a manual QA checklist. Icons (the P0 release blocker) are already fixed in a prior commit.

**Architecture:** Two independent code fixes in the existing extension, no new modules or dependencies. `extension/background.js` gets a `settingsReady` promise gate so message handlers wait for `chrome.storage.local.get` before trusting cached settings. `extension/content.js` gets a one-line staleness guard in `requestTranslation` and a shared `getPlayerContainer()` helper reused by both the overlay mount point and the `MutationObserver` target.

**Tech Stack:** Vanilla JS, Chrome Extension MV3, Node built-in test runner (`node --test`), no new dependencies.

## Global Constraints

- All work happens inside `extension/` unless a task says otherwise.
- Test command: `cd extension && npm test` (must stay at 15+ passing, 0 failing after each task).
- **Every `git commit` requires explicit user approval before it runs** — this project's `CLAUDE.md` states commits must not happen without the user's sign-off, regardless of size. Pause and ask before running each commit step below; do not run it automatically.
- Follow existing commit style: `type(scope): summary` (see `git log --oneline`), imperative mood, no body needed for small fixes.
- Do not change `extension/manifest.json`'s content-script declaration to `"type": "module"` — MV3 content scripts run as classic scripts; introducing static `import`/`export` into `content.js` would break the shipped extension. This is why Task 2 and Task 3 are verified by the existing regression suite plus manual QA rather than new unit tests.

### Task 1: Fix MV3 service-worker settings-init race in `background.js`

**Files:**
- Modify: `extension/background.js:1-22` (add `settingsReady` gate), `extension/background.js:33-46` (await it in the message listener)
- Test: `extension/tests/background-settings-race.test.js` (new)

**Interfaces:**
- Consumes: nothing new — reuses `chrome.storage.local`, `chrome.runtime.onMessage` already used by `background.js`.
- Produces: `settingsReady` (module-level `Promise<void>`) inside `background.js`, resolved once `cachedEnabled`/`cachedApiKey` are populated from storage. Not exported (background.js has no exports today); the test drives it indirectly through the mocked `chrome.runtime.onMessage` listener.

- [ ] **Step 1: Write the failing test**

Create `extension/tests/background-settings-race.test.js`:

```js
import { test } from "node:test";
import assert from "node:assert/strict";

function installChromeMock({ storageDelayMs, enabled, deeplApiKey = "" }) {
  let messageListener;

  globalThis.chrome = {
    runtime: {
      getURL(path) {
        return `chrome-extension://test/${path}`;
      },
      onMessage: {
        addListener(fn) {
          messageListener = fn;
        },
      },
    },
    storage: {
      local: {
        get(_defaults, callback) {
          setTimeout(() => callback({ enabled, deeplApiKey }), storageDelayMs);
        },
      },
      onChanged: {
        addListener() {},
      },
    },
  };

  return {
    sendMessage(message) {
      return new Promise((resolve) => {
        messageListener(message, {}, resolve);
      });
    },
  };
}

async function importFreshBackground() {
  return import(`../background.js?case=${Math.random()}`);
}

test("GET_ENABLED arriving before storage resolves still reports the real stored value", async () => {
  globalThis.fetch = async () => {
    throw new Error("network disabled in test");
  };
  const chromeApi = installChromeMock({ storageDelayMs: 20, enabled: false });
  await importFreshBackground();

  const response = await chromeApi.sendMessage({ type: "GET_ENABLED" });

  assert.equal(response.enabled, false);
});

test("TRANSLATE_TEXT arriving before storage resolves does not translate while really disabled", async () => {
  globalThis.fetch = async () => {
    throw new Error("network disabled in test");
  };
  const chromeApi = installChromeMock({ storageDelayMs: 20, enabled: false });
  await importFreshBackground();

  const response = await chromeApi.sendMessage({ type: "TRANSLATE_TEXT", text: "안녕" });

  assert.equal(response.ok, false);
  assert.equal(response.error, "Extension disabled");
});
```

- [ ] **Step 2: Run test to verify it fails**

Run: `cd extension && node --test tests/background-settings-race.test.js`

Expected: both tests **FAIL**.
- Test 1 fails with `AssertionError`: `response.enabled` is `true` (the `DEFAULT_ENABLED` default), not `false`, because `GET_ENABLED` responds synchronously before `chrome.storage.local.get`'s 20ms-delayed callback runs.
- Test 2 fails because `cachedEnabled` is still `true` when the message arrives, so the code skips the `"Extension disabled"` branch and falls through to `translateText(...)`, which throws the mocked `"network disabled in test"` error instead of returning `"Extension disabled"`.

- [ ] **Step 3: Implement the settings-ready gate**

In `extension/background.js`, replace:

```js
chrome.storage.local.get({ enabled: DEFAULT_ENABLED, deeplApiKey: "" }, (result) => {
  cachedEnabled = result.enabled;
  cachedApiKey = result.deeplApiKey;
});
```

with:

```js
const settingsReady = new Promise((resolve) => {
  chrome.storage.local.get({ enabled: DEFAULT_ENABLED, deeplApiKey: "" }, (result) => {
    cachedEnabled = result.enabled;
    cachedApiKey = result.deeplApiKey;
    resolve();
  });
});
```

Then replace the `onMessage` listener's two branches:

```js
chrome.runtime.onMessage.addListener((message, _sender, sendResponse) => {
  if (message?.type === "GET_ENABLED") {
    sendResponse({ enabled: cachedEnabled });
    return false;
  }

  if (message?.type === "TRANSLATE_TEXT") {
    (async () => {
      const text = typeof message.text === "string" ? message.text : "";
      if (!cachedEnabled) {
        sendResponse({ ok: false, text, error: "Extension disabled" });
        return;
      }
```

with:

```js
chrome.runtime.onMessage.addListener((message, _sender, sendResponse) => {
  if (message?.type === "GET_ENABLED") {
    settingsReady.then(() => sendResponse({ enabled: cachedEnabled }));
    return true;
  }

  if (message?.type === "TRANSLATE_TEXT") {
    (async () => {
      await settingsReady;
      const text = typeof message.text === "string" ? message.text : "";
      if (!cachedEnabled) {
        sendResponse({ ok: false, text, error: "Extension disabled" });
        return;
      }
```

The rest of the `TRANSLATE_TEXT` body (cache lookup, `translateText` call, catch block) is unchanged.

- [ ] **Step 1: Confirm current regression baseline**

Expected: `# pass 17`, `# fail 0` (from Task 1).

- [ ] **Step 2: Implement the staleness guard**

In `extension/content.js`, replace:

```js
function requestTranslation(text) {
  if (!enabled) return;

  chrome.runtime.sendMessage({ type: "TRANSLATE_TEXT", text }, (response) => {
    if (!enabled) return;

    if (chrome.runtime.lastError) {
      renderText(text, "error");
      return;
    }

    renderText(response?.text || text, response?.ok ? "translated" : "error");
  });
}
```

with:

```js
function requestTranslation(text) {
  if (!enabled) return;

  chrome.runtime.sendMessage({ type: "TRANSLATE_TEXT", text }, (response) => {
    if (!enabled) return;
    if (text !== lastCaptionText) return; // a newer caption replaced this one while we were waiting

    if (chrome.runtime.lastError) {
      renderText(text, "error");
      return;
    }

    renderText(response?.text || text, response?.ok ? "translated" : "error");
  });
}
```

`text` is always the caption string that was current when this request was sent (`scheduleCaptionCheck` only calls `requestTranslation(text)` after setting `lastCaptionText = text`). If a newer caption — or the 1-second clear timer — has since changed `lastCaptionText`, this response is stale and must not render.
